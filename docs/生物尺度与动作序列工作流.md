# 生物尺度与动作序列工作流

汇总生物类别尺度档案、人物槽布局、landmark 标注、母版集合检查及动作序列注册。身体尺度只有绑定 landmark 和已核准类别档案后才能量化；canvas、alpha bbox、采样倍率和动作/运行状态分别报告。

## 统一操作约束

- 每批任务使用唯一 operation ID，冻结来源路径、像素尺寸、SHA、原生槽位和实际算法版本。
- `check` 不写素材；`run` 只写新隔离目录；`verify` 从冻结输入重算并核对输出。
- 原始高清母版、处理候选和正式 3X 交付分开管理；不把低倍率输出升格为母版。
- 报告中的 `PASS` 只对其明确列出的合同负责；艺术身份、实际地图拼接和游戏运行需分别核验。

## 本地自动描点与相对注册候选

`creature-auto-pose` 是本地人体姿势估计的审图工具。输入可以是一张真正 RGBA 的高清 PNG，或 `scale-audit freeze` 的官方全槽冻结 JSON。批量输入重新核对 inventory SHA、官方身份/组帧/原生 canvas/crop/origin/资源名和当前目录的文件快照；同 SHA 图片只推理一次，每个官方逻辑槽仍单独保留绑定。单 PNG 没有官方绑定。产出模型、输入、软件脚本、每槽图像 SHA、原图 17 点及水平翻转复测、风险提示、缩小的对照图和 HTML；不修改任何源文件。

界面：“批量任务中心 → 自动身体描点 creature-auto-pose”，选择 PNG 或冻结 JSON，选择 `run`，处理结束后再选 `verify`。也可使用 CLI，示例如下，路径和 SHA 换成当前实际值：

```powershell
$exe = '{H3TierExport}\dist\H3TierExport.exe'
$inputFile = 'D:\...\0_0.png'
$id = 'one-creature-pose-r01'
$out = "{H3TierExport}\build\experiments\creature-auto-pose\$id"
$inputSha = (Get-FileHash -LiteralPath $inputFile -Algorithm SHA256).Hash.ToLowerInvariant()
& $exe creature-auto-pose check  --manifest $inputFile --manifest-sha256 $inputSha --outdir $out --operation-id $id
& $exe creature-auto-pose run    --manifest $inputFile --manifest-sha256 $inputSha --outdir $out --operation-id $id
& $exe creature-auto-pose verify --manifest $inputFile --manifest-sha256 $inputSha --outdir $out --operation-id $id
```

有明确的可比较姿势与朝向时，可制作 `h3.creature.auto-pose.request.v1` 请求，引用已冻结的 `audit_manifest: {path, sha256}`，并填写 `comparison_groups` 数组。每组需给出 `id`、`pose_group`、`direction`、`reference`（例如 `0_0`）和 `slots`（例如 `["0_0", "0_1"]`）；同一个槽不得同时出现在两组。工具输出多骨段尺度建议及仅供审图的等比 APNG；它将估计髋部对齐，不表示游戏中真实的脚底轨迹或位置。比较组应由操作者按动作语义指定，不能跨不相容姿势机械归一化。

比较组可选 `visual_feature_alignment`，为同一朝向、相近姿势提供独立的纹理匹配建议。`{"mode":"full_opaque_foreground"}` 使用透明图的实色区域；若武器、披风或背景特征会干扰，可用 `{"mode":"explicit_source_regions", "regions":{"0_0":[x0,y0,x1,y1],"0_1":[x0,y0,x1,y1]}}` 分别指定实际源 PNG 内的候选身体区域。每个比较槽都要有自己的实际坐标。算法输出来源 SHA、匹配数量、内点分布、残差、相对等比变换和风险标记，只读输入，不应用变换。它匹配的是纹理，不是识别解剖结构；即便匹配很多，也不能单独证明人物尺寸、身份或原生注册。

该可选检查依赖本地 provider 的 OpenCV（SIFT 和 RANSAC）；未安装时显示 `UNAVAILABLE`，原描点功能继续可用。报告记录 OpenCV 版本和构建信息哈希。当前实现仍处于源码／候选验证阶段，正式 `dist` 是否具有此能力以其实际版本和发布回执为准。

Windows 资源管理器按整张 PNG 缩放缩略图：原生完整画布和紧裁母图即使同一人物也会看起来差很多。比较时要将每帧经核实的 K 与平移放回各自官方原生画布，再用共同显示倍率播放；单纯切换到源 PNG 的同像素倍率仍不能消除不同 K。K 或位置未验证时只能标记候选，不能宣称最终注册通过。

`AUTO_ESTIMATED_REVIEW_REQUIRED` 和翻转分歧只供筛选。原始分数不是经校准的正确率，没出现警告也不能证明点位、身体尺度、肢体或动作正确。人体模型不适合作为飞龙、骑乘体等物种的自动验收模型；应分物种选用并验证模型。遮挡时需检查原图，必要时使用下面的人工标注工具确认身体轴线和真实根部，结合官方 DEF 几何、明确动作轨迹和可靠的 K 再通过既有 `creature_sequence_registration` / `scale-layout` 处理。不能将候选点伪装为 `visual-anatomical-landmarks` 或将预览升格母版/3X。

当前本机 provider 位于 `build/creature-auto-pose-provider`，包含独立 Python 3.13 环境、ONNX Runtime CPU 与 OpenMMLab RTMPose-m body7 模型。模型和 provider 清单 SHA 在每份报告中记录；代码执行只读本机文件，实际模型数据的授权与再分发范围尚未确认，不默认打包进入发行件。

### 骑乘英雄：马和骑手分开候选、整体复核

`hero-mounted-pose` 以 RTMPose AP-10K 分别估计马体关节点，再以 body7 模型在候选骑手区域估计人体点位。两次点位都只用于复核。马背、腿、坐姿、装备和固定原生位置必须综合考虑；马体的颈部到尾根不是地面锚点，不能凭它自动修正或批准。观察发现当前 AH00_ 侧面马体模型能提供有用候选，正面和背面容易把披风误认作头部或肢体；翻转一致性也无法保证预测正确。不同朝向不要直接比较同一骨段的源像素长度。

官方 inventory 中 AH 不属于 `creatures` 分类，因此不拿 `scale-audit freeze` 的生物身份入口冒充英雄入口；先使用：

```powershell
$inventory = '{H3-assets}\CompleteOfficialRelease-20261006-v1\codex-map\native-resource-inventory.json.gz'
$inventorySha = (Get-FileHash -LiteralPath $inventory -Algorithm SHA256).Hash.ToLowerInvariant()
$masters = '{H3-assets}\CompleteOfficialRelease-20261006-v1\codex-高清母版\地图\AH00_'
& $exe hero-mounted-pose freeze --inventory $inventory --inventory-sha256 $inventorySha --identity AH00_ --masters-dir $masters --operation-id ah00-pose-r01
```

生成的 `build/experiments/hero-pose-requests/ah00-pose-r01.json` 可载入任务中心，或用 `hero-mounted-pose check/run/verify`。显式同姿势比较请求同上，输出目录改为 `build/experiments/hero-mounted-pose/<operation-id>`。预览中统一的是估计马体根部，用于查看大小，不代表真实坐标注册；同一动作组应另核脚部接触、马鞍与骑手位置、尾巴/披风及武器完整性。

## 类别尺度档案、开工草案与全槽尺寸报告（1.3.3）

> 合并来源：`CREATURE-SCALE-WORKFLOW.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

### 软件入口

- “文件夹动画预览/打包”新增“逐帧适配窗口／整组同倍率”切换，默认整组同倍率；同时显示当前`<DEF>.DEF`、实际PNG文件名、画布像素和预览倍率。
- “批量任务中心 → 开工前类别尺度草案 scale-draft”。
- “批量任务中心 → 制作后全槽尺寸检查 scale-audit”。

两个尺度任务都支持检查、生成和复验。生成的是JSON、Markdown和可筛选HTML，**不修改PNG、不自动归一化、不产生缩略图或多倍率副本**。预览中的同倍率只表示同一组使用相同PNG像素比例；它不等于身体已经一致，也不会改变APNG导出或原生DEF几何。

### 四类工作档案

| 类别参数 | 显示名称 | 衡量范围 | 脚底／根部 |
|---|---|---|---|
| `infantry` | 步兵 | 完整主体 | 支撑脚 |
| `mage` | 法师 | 完整主体，不能按法杖外框估身体 | 支撑脚或根部 |
| `mounted` | 骑乘单位 | 骑手、坐骑和装备整体；骑手单独标点不足以衡量整组 | 坐骑接地位置 |
| `large_creature` | 大型生物 | 完整主体；翼展、武器等不能直接变成身体高度 | 脚部或身体根部 |

所有类别默认`DRAFT / NOT_MEASURED`。没有核准样本时，工作画幅、主体构图占比、锚点和透明留边目标留空，不从DEF名或bbox猜数值。可输入用户提出的布局目标，但它们仍标为未测量的草案。

提供真实核准样本后记录其实际画布、透明主体框、留边和有标点的根部；这些是工作布局资料，不覆盖每个正式槽自己的`canvas/crop/origin`。不要求全部帧同画布、同裁片或同高度。类别档案输出是任务草案，不替代项目现有唯一美术标准。

### 先冻结官方资料与当前目录

例子中的路径换成当前机器的真实路径，SHA用实际文件计算；不依赖固定浏览器、CDP端口或账号。

```powershell
$ScaleTool = "D:\...\H3TierExport\dist\H3TierExport.exe"
$ScaleInventory = "D:\...\codex-map\native-resource-inventory.json.gz"
$ScaleInventorySha = (Get-FileHash -LiteralPath $ScaleInventory -Algorithm SHA256).Hash.ToLowerInvariant()
& $ScaleTool scale-draft freeze --inventory $ScaleInventory --inventory-sha256 $ScaleInventorySha --identity CENCH --category mage --operation-id cench-scale-draft-r01
& $ScaleTool scale-audit freeze --inventory $ScaleInventory --inventory-sha256 $ScaleInventorySha --identity CTROLL --category large_creature --masters-dir "D:\...\CTROLL" --operation-id ctroll-scale-audit-r01
```

软件自动从所选inventory填写所有真实组／帧、原生画布、裁片、原点、资源和LOD来源，并绑定inventory SHA；不会限定只能读`H3sprite.lod`，也不会丢掉inventory中的`H3ab_spr.lod`身份。faction／form若inventory没有，可显式用`--faction/--form`补充；不凭DEF名猜基本／升级形态。

`freeze`返回manifest路径、SHA及正确输出目录。请求保存在工具`build/experiments/scale-requests/<operation_id>.json`。GUI载入此manifest，依次检查、生成、复验；CLI等价为：

```text
H3TierExport.exe scale-audit check  --manifest ABSOLUTE.json --manifest-sha256 SHA --outdir PRODUCT/build/experiments/scale-audit/ID --operation-id ID
H3TierExport.exe scale-audit run    --manifest ABSOLUTE.json --manifest-sha256 SHA --outdir PRODUCT/build/experiments/scale-audit/ID --operation-id ID
H3TierExport.exe scale-audit verify --manifest ABSOLUTE.json --manifest-sha256 SHA --outdir PRODUCT/build/experiments/scale-audit/ID --operation-id ID
```

开工草案将命令和输出目录换为`scale-draft`。只能写对应工具根下的新operation；既有外来或失败半成品目录不会覆盖。同一完整任务重跑执行复验。目录新增PNG、源图或inventory改变时重新冻结新任务，不能把旧快照当当前通过。

### 可选：绑定尺度上下文

`freeze --context ABSOLUTE.json --context-sha256 SHA`可输入`h3.creature.scale-context.v1`。主要字段：

- `proposed_layout`：可选`work_canvas_pixels`、`subject_occupancy_target`、`root_anchor_pixels`、`transparent_margin_target`。它们是明确提出的草案目标，不自动应用到图片。
- `art_standard`：项目现有美术标准的`path/sha256`引用。报告只引用，不改标准。
- `approved_sample`：`key/image/approval/registration`。image是PNG的`path/sha256`；approval绑定`h3.creature.scale-sample-approval.v1`的真实`key/image_sha256/status`记录，status为已有`assistant_art_pass`或真实`human_approved`。不生成或伪造批准记录。registration可选，必须是对应图片与原生槽的真实motion回执。
- `working_registrations`：`[{key, receipt:{path,sha256}}]`。只有目标倍率、PNG SHA、原生槽、crop尺寸和origin都匹配，才报告K。该栏明确是回执与尺寸绑定，不假称已重放渲染器。
- `landmarks`：指向下面的哈希绑定解剖标点文件。
- `source_pixel_reference`：可选的同一冻结槽集内参考槽，填写`key`与准确`image_sha256`。这是未审批的相对诊断锚点，不替代`approved_sample`或实际注册回执。
- `deliveries_3x`：`[{key,image:{path,sha256},receipt:{path,sha256}}]`。按独立target_scale=3、crop×3和origin×3核对；即使母版缺失，也分别报告已有3X状态，绝不把3X升格补母版。

解剖文件schema为`h3.creature.scale-landmarks.v1`，`frames`每项包含：

```json
{
  "key": ["def", "DEFNAME", 0, 0],
  "image_sha256": "SHA_OF_THE_EXACT_ANNOTATED_IMAGE",
  "coordinate_space": "source_pixels",
  "measurement_scope": "whole_subject",
  "pose_group": "EXPLICIT_COMPARABLE_POSE_GROUP",
  "direction": "EXPLICIT_DIRECTION",
  "root_anchor_pixels": [100, 400],
  "paths": {
    "head": [[100, 50], [100, 90]],
    "torso": [[100, 90], [110, 200]],
    "body": [[100, 50], [110, 200], [100, 400]]
  }
}
```

以上仅为结构示例，坐标不能复制给真实角色。点位须针对被引用的真实图片标注，不能从Alpha自动推断。骑乘类别改为`measurement_scope=rider_mount_and_equipment`，并补`rider_axis/mount_axis/equipment_extent`路径；缺项仍为`NOT_MEASURED`。同一槽的旧核准图和新候选可分别按不同图片SHA绑定标点。

只有同一明确姿势组、方向、衡量范围且有有效K的标点，才比较绝对身体尺度。只有标点而无K时，报告源像素路径长度与比例，标为`MEASURED_SOURCE_PIXELS_ONLY`。若显式提供`source_pixel_reference`，工具只在双方源PNG分辨率、姿势组、方向和衡量范围一致时，附加源像素路径相对差异；结果标为诊断，不代表绝对尺度、审批或自动缩放。分辨率不同则为`NOT_COMPARABLE_SOURCE_RESOLUTION_DIFFERS`，不会把不同生成分辨率当人物缩放。绝对动作组偏差仍相对同一个核准参考计算，不仅与各组自身中位值比较，避免掩盖整组偏大和单帧组偏差。

### 报告中的独立项目

全槽逐项列出：身份、组帧、官方命名、缺漏／歧义、SHA、实际PNG画布、原生canvas/crop/origin、K及依据、透明框／留边、解剖测量、相对参考偏差、正式3X与运行状态。HTML中的身体状态可展开查看原始长度、比例和原因。

几何、采样倍率、身体尺度、正式3X、运行各自列项。bbox只提示布局／FIT，不触发自动缩放、重绘或美术通过；图片已有生产审批保持原状态。此报告没有实际启动游戏，运行一栏保持`NOT_VERIFIED`。

`NOT_MEASURED`只表示本报告没有该项测量证据，不代表已有母版被拒绝，也不据此排入重绘。

## 单人物静态槽尺度校正

> 合并来源：`SUBJECT-SCALE-LAYOUT.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

`scale-layout catalog|check|run|verify` 将已有人物高清母版按明确的身体测量和接地点重新注册。它不调用模型，不 resize、不锐化、不删 Alpha，也不生产正式3X。输出通过整数裁切和透明补边复制全部正 Alpha 像素；原始母图保持原字节。最终规格仍由原生 exporter 单次等比例采样。

适用：完整、清晰的现有单人物，只是画布留白／人物显示尺度／位置不一致。工具支持明确选择的静态 DEF 槽，原生身份、canvas/crop/origin 直接来自 SHA 绑定 inventory，包含地图英雄类别。一个身份/组若包含多帧，继续使用原动画 prepare-sequence 流程，不用此静态工具绕过整组尺度和时序合同。

不适用：缺肢多肢、错误装备、被截断的原画、低倍率派生、糊画或不同部件比例冲突。缺少母版、身体目标与正 Alpha 边界无法同时满足，记为 NEEDS_REDRAW；不偷偷缩小人物、压扁身体或擦除边缘来取得 FIT。

### 同一尺度档案同时服务本地修复和重新绘制

输入 `h3.art.production-profile.v1` 是项目唯一美术规范的具体执行档案，绑定规范版本/SHA及已选真实高清参考，不另立项目美术标准。按朝向分开填写：主身体度量、辅助结构度量、原生单位目标、容差、接地点。骑乘对象应量坐骑身体、骑手躯干等稳定结构，长矛、尾巴、披风只参与容纳检查，不能作为身体高度。

每张母版填写 `visual-anatomical-landmarks`、source SHA、source_pixels 坐标和接地点。工具由主身体度量求合适采样密度 K，并检查辅助部位比例；遍历可行整数 K，只接受身体目标容差与全部正 Alpha FIT 同时成立的解。调整画布及位置不改变绘画像素；显示放大通过缩减多余透明留白达成，不插值放大高清母版。

1.3.6补充：整数K已有解时保持原结果；仅`native-canvas`在整数无解时，以canvas宽高最大公约数为分母搜索精确有理K。完整画布宽高仍为整数且原生长宽比完全相等；像素只按整数坐标复制，裁片边界按真实K精确检查，保留所有正Alpha及一像素安全边。报告附`editing_scale_exact`分子/分母。`native-crop`仍使用整数K；此能力不改变正式3X采样、原生几何或任何阈值。

GPT 的输出尺寸无需精确可控。生成时绑定身份图和本朝向参照，要求完整单人物及真实透明背景；生成后重新量同一身体度量并运行相同档案。实际分辨率不足、身体比例错误或装备越槽才针对该张重绘。`generation-brief.md` 从同一档案生成中文执行要求，不凭提示词声称尺寸已经通过。

### 清单与输出

清单 schema 为 `h3.subject-scale-layout.manifest.v1`，字段：`operation_id/native_inventory/profile/expected_slots/items`。前两项资料引用均为绝对 path/SHA；source 另含 pixels。expected_slots 是本次明确槽位清单，items 必须一一对应，不把五朝向静态样本当作完整45帧动画。

每项包括 `key/profile_direction/source/measurement`；source 缺失时显式为 null。measurement 包含准确 image_sha256、coordinate_space=source_pixels、method=visual-anatomical-landmarks、anchor_source，以及按 profile 度量名称填写的折线路径 paths。

输出限新目录 `build/experiments/scale-layout/<operation-id>`，按身份目录保存 `<group>_<frame>.png`，附 receipt.json 与 generation-brief.md。check 不写图，verify 重放布局并核对 PNG SHA、RGBA 像素和执行要求。工具不会覆盖母版、自动批准艺术或部署。通过后由素材 owner 结合正常尺寸浅色底目视、来源链和正式注册将可用结果入库；必要编辑父图保留来源引用，被淘汰内容按项目规则新增移入用户待删除批次。

## 生物动画的身体尺度、根部轨迹与固定相机

> 合并来源：`docs/creature-sequence-registration.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

这是工具使用说明。唯一美术标准仍由项目现有规范提供，执行档案不是另一份标准。

### 两条输入路径

- 已有真实高清帧：`scale-layout` 的序列注册按身体标点确定源像素/原生单位，按显式身体根部轨迹放置。无损裁切透明留边、补边和移动；不重画、不resize母版，不按每帧Alpha框填满裁片。
- 有真实模型、骨架与Actions：现有 `blender-actions` 沿同一正交相机采样全部动作。新增可选 `motion_consistency`，在渲染前检查实际骨骼段、求值后网格段、固定相机和逐槽root轨迹。没有合同时明确未测量。

图像画布大小、身体尺度、根部轨迹、动作语义、正式3X和实机验收分别记录。俯身、展翅和转向可以改变外框；不因此缩放整个角色。飞行、跃起、死亡可以有位移，必须由相应轨迹声明，不能一律锁脚底。

### 已有高清序列：冻结请求

使用 `h3.creature.sequence-registration.manifest.v1`，保留原有 `native_inventory`、`profile`、`expected_slots` 与 `items`。要求 `output_layout: native-canvas`，以完整原生坐标注册，最终导出仍只保留native crop3X。

`implementation` 的schema为 `h3.creature.sequence-registration.readers.v1`，提供 `layout_reader` 和 `sequence_reader` 的路径/SHA。可指向不可变读者快照；执行的两份读者字节必须与请求绑定一致。源码改变后创建新冻结请求，不改签历史请求。

`sequence_contract`：

```json
{
  "schema": "h3.creature.sequence-registration.contract.v1",
  "native_def": {"path": "ABS/DEFNAME.def", "sha256": "ACTUAL_SHA"},
  "groups": [0],
  "logical_scope": [["def", "DEFNAME", 0, 0]],
  "scale_policy": "anatomical-targets",
  "camera_policy": "fixed-native-units",
  "root_semantics": "本形态实际选定的身体根部定义",
  "trajectory_units": "native_canvas_1x",
  "aliases": []
}
```

示例只展示结构，不能把虚构槽位、SHA或目标复制给真实生物。DEF须由实际LOD核对提取，名称与身份一致；二进制头与inventory逐槽相符。选定组必须完整覆盖。同offset只选一个绘制owner，其他逻辑槽通过 `aliases:[{key,owner_key,source}]` 绑定；别名源PNG必须与owner同字节。

profile继续使用 `h3.art.production-profile.v1`，绑定当前标准路径、版本、SHA和真实参考图。每个 `directions` 规则增加明确 `pose_group`、`direction`、`clearance_native`（通常为1..16原生像素），提供至少两个明确身体指标和目标原生长度。原版内容确实贴边时，可明确设置 `clearance_native:0` 并同时设置 `allow_native_crop_edge_contact:true`；软件仍须完整保留所有正Alpha，零留边不代表艺术、3X或运行通过。`primary_metric`不应是Alpha框或武器／翼展范围。

每个owner的 `measurement` 保留源PNG SHA、source_pixels坐标、`visual-anatomical-landmarks`方法、`anchor_source`和各指标折线，增加 `annotation_author: assistant|human`、与规则一致的 `pose_group/direction`。每个item必须显式提供 `root_offset_native:[dx,dy]`，表示相对该规则身体根部目标的动作轨迹。零位移也显式写出，不猜动作或朝向。

这些标点必须来自实际图像。AI估计与人类标点如实区分；记录误差范围，不称作自动解剖识别。目标须在相容姿势/方向中使用，不能把倒地姿势与站立投影强制同高。

### 检查、无损适配、重放

GUI选择“人物尺度与批量质量验证 scale-layout”，载入上述冻结清单，依次检查、运行、验证。CLI可用同样的 `check|run|verify`，也可显式使用：

```text
H3TierExport.exe scale-layout sequence-check --manifest ABS.json --manifest-sha256 SHA --outdir PRODUCT/build/experiments/scale-layout/ID --operation-id ID
H3TierExport.exe scale-layout sequence-run --manifest ABS.json --manifest-sha256 SHA --outdir PRODUCT/build/experiments/scale-layout/ID --operation-id ID
H3TierExport.exe scale-layout sequence-verify --manifest ABS.json --manifest-sha256 SHA --outdir PRODUCT/build/experiments/scale-layout/ID --operation-id ID
```

软件在全体owner都满足身体目标、比例和正Alpha FIT之后才写候选。骨骼姿态／装备布局或标点有冲突时返回问题，不静默缩小该帧，不擦Alpha，不自动要求重画。旧静态schema继续拒绝多帧，不能借新功能放宽旧合同。

输出是无损适配中间图、`receipt.json`、`native-review-manifest.json`、`export-aliases.json`。源像素保留，整数或精确分数密度K只描述适配映射。此处尚未采样、不算新母版，也不算正式3X。别名handoff是原生offset绑定资料，不是“又生成了一帧”。

这里的每帧 `editing_scale` 是“未重采样源像素/原生单位”的输入注册密度，源图取景不同可以有不同值；它不是旧prepare-sequence的统一工作倍率。整组由原采样器直接进入共同的3X目标网格。若继续使用旧的统一prepared K路径，仍须按原合同求全组可行K交集，不能串用这两个定义。

### 动作尺度跨度与轨迹筛查

新源码中的 `sequence-temporal` 读取已完成 `sequence-verify` 的布局回执，重新重放验证源图、描点、官方几何和候选像素，然后比较同一动作组、同姿态、同朝向和同名身体指标。即便每帧对参考的误差都在±10%内，两帧之间仍可能相差超过10%；报告因此另列整组最大／最小尺度跨度和相邻帧变化。只有明确声明循环的组才计算末帧到首帧。根部位置是制作人提供的轨迹，不自动假设支撑脚静止；只有显式提供阈值才标记根部位移提醒。

```text
H3TierExport.exe sequence-temporal freeze --layout-receipt ABS/receipt.json --layout-receipt-sha256 ACTUAL_SHA --operation-id NEW_ID --loop-group 6 --root-step-warn-native 1.0
H3TierExport.exe sequence-temporal check  --manifest FROZEN.json --manifest-sha256 ACTUAL_SHA --outdir PRODUCT/build/experiments/sequence-temporal/NEW_ID --operation-id NEW_ID
H3TierExport.exe sequence-temporal run    --manifest FROZEN.json --manifest-sha256 ACTUAL_SHA --outdir PRODUCT/build/experiments/sequence-temporal/NEW_ID --operation-id NEW_ID
H3TierExport.exe sequence-temporal verify --manifest FROZEN.json --manifest-sha256 ACTUAL_SHA --outdir PRODUCT/build/experiments/sequence-temporal/NEW_ID --operation-id NEW_ID
```

组号、阈值和SHA只是示例，须按实际动画填写；可重复指定 `--loop-group`，不指定就不猜循环。默认跨度与相邻差提醒阈值均为10%，可显式调整；根部阈值不填则只列数值、不作警告。GUI任务中心的“动作尺度与轨迹筛查”载入 `freeze` 返回的清单，依次检查、运行、验证。报告可区分 `REVIEW_REQUIRED`、`NOT_MEASURED` 和不可比；描点误差、透视、遮挡、正常动作以及真实播放仍须观察。它不依靠透明框推断身体、不自动改图、不自动重绘、不授予美术或游戏通过。该入口以当前构建及发布门禁的实际结果为准，源码更新不代表已更新正式 dist。

### 唯一3X候选采样与实际审阅

将生成的 `native-review-manifest.json` 交给原 `native-review`。请求显式 `[3]`、严格比例、native-canvas输入与native-crop输出；从高清适配域在内存中单次采样全原生网格，再按实际crop/origin提取唯一3X，不落盘整幅副本、1X/2X或拼板。

```text
H3TierExport.exe native-review --manifest GENERATED.json --manifest-sha256 SHA --outdir PRODUCT/build/experiments/native-review/NEW_ID
```

核对输出尺寸crop×3、origin×3、单次采样、裁片外正Alpha为0及源/输出SHA。最终owner仍须沿原业务writer做生产准入，并按 `export-aliases.json` 的真实offset关系绑定逻辑别名。母版源、适配域、3X候选及正式交付分别记账；native-review报告不自动改签为expand交付回执，也不能再把3X候选当源重采样一次而声明仅采样一次。此工具不写共享资产索引、母版或正式游戏。

播放时按crop/origin重建同一原生坐标，固定显示倍率；不能每帧fit窗口、居中不同裁片或把模板K当身体尺度证明。动作顺序、循环类型、跨组衔接和实际运行独立验收。

### Blender Action的一致性合同

在现有manifest里增加可选 `motion_consistency`：

```json
{
  "schema": "h3.blender.motion-consistency.v1",
  "calibration_key": [2, 0],
  "rigid_segments": [
    {"id":"skull","bone":"Head","a":[0,0,0],"b":[0,1,0],"max_relative_change":0.02},
    {"id":"chest","space":"evaluated_mesh","object":"Body","vertices":[12,24],"max_relative_change":0.02}
  ],
  "root": {
    "bone":"Root","point":[0,0,0],"max_error_native":0.25,
    "track":[{"native_group":2,"native_frame":0,"expected_pixel_1x":[200,267]}]
  }
}
```

这些是虚构结构示例，骨骼、顶点、槽位和坐标均需换成实际模型的数据。root track必须覆盖全部映射槽；合法动作位移由各槽目标明确给出。用于身体量度的刚性段至少两条，可来自bone local点或求值后网格顶点；网格顶点由已pin模型固定，不能在换模型后复用旧编号。

先在明确校准槽采集世界单位段长，再在映射的实际帧/子帧检查尺度变化、相机矩阵与正交参数、渲染尺寸及root投影。网格段还能发现骨架未变、实际网格却被拉大的情况。记录的 `rigid_segment_scale_pass`只代表声明段的一致性，绝不等于绝对艺术体量、解剖或所有帧间动作语义已通过。

检查在输出图片前运行。回执复验会重算已记录测量的数学关系和全槽覆盖；这不冒称独立重跑Blender。模型/源代码/时间来源的原pin、输出隔离及原生Alpha门禁继续有效。

真正的连贯动作仍需同一模型/骨架的可编辑Action，明确蓄力、接触、恢复、起步/停止、转身桥与循环端点。仅有一张生成图或导出脚本不能补出真实骨架或缺失姿势。无真实模型时先使用已有帧注册路线；大转身、遮挡或结构不一致不能靠等比例注册解决。

### 验证范围

新增序列反例覆盖：翼展变化不改变身体尺度、显式root运动、真实DEF与别名、错源SHA/错方向/缺组帧、比例或FIT冲突、读者漂移、单套3Xhandoff、旧静态合同仍拒绝多帧。

Blender反例覆盖：固定模型/相机的正常采样通过；骨骼缩放、无理由root偏移、镜头缩放、仅网格伸长分别被拒绝。实际运行可用环境变量 `H3TIEREXPORT_BLENDER` 指向现有Blender，执行 `tests/blender_motion_consistency_contract.py`。诊断箱体与合成骨架不是已完成的生物资产。

## Creature anatomical landmark annotation

> 合并来源：`docs/creature-landmark-annotation.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

`creature_landmark_annotator.py` is a local manual point-selection companion for H3TierExport scale-audit. It consumes a current frozen `h3.creature.scale-report.manifest.v1`, reads the selected official slot PNGs without editing them, and writes a new `h3.creature.scale-landmarks.v1` JSON file bound to each source PNG SHA.

### Freeze a current source snapshot

Use the current H3TierExport executable and actual product inventory. Re-freeze whenever the PNG directory or official inventory changes:

```powershell
$tool = '{H3TierExport}'
$exe = "$tool\dist\H3TierExport.exe"
$inventory = '{H3-assets}\CompleteOfficialRelease-20261006-v1\codex-map\native-resource-inventory.json.gz'
$inventorySha = (Get-FileHash -LiteralPath $inventory -Algorithm SHA256).Hash.ToLower()
$masters = '{H3-assets}\CompleteOfficialRelease-20261006-v1\codex-高清母版\生物\中立生物\CTROLL'
& $exe scale-audit freeze --inventory $inventory --inventory-sha256 $inventorySha --identity CTROLL --category large_creature --masters-dir $masters --operation-id ctroll-landmarks-current-r01
```

The resulting manifest binds the exact current slots, images, SHAs and native geometry. The annotator rechecks the inventory and image hashes; if anything changed, it stops and asks for a new freeze.

### Mark a sample

Select only the frames that have the same manually reviewed pose family and direction. For example, mark one standing scale anchor with:

```powershell
$manifest = "$tool\build\experiments\scale-requests\ctroll-landmarks-current-r01.json"
$out = "$tool\build\experiments\scale-layout\landmarks\ctroll-standing-anchor-r01.json"
python -B "$tool\scripts\creature_landmark_annotator.py" --manifest $manifest --key 2_5 --out $out
```

In the window:

1. Enter an explicit `pose_group` and `direction`; the tool does not guess either.
2. Select `head`, `torso`, or `body`, then click the path points in the displayed source image. Select `root` and click the support-foot or body-root contact point.
3. The default `整批同源像素倍率` view uses one display zoom for every selected canvas, so differing canvas dimensions do not individually resize the artwork on screen. `逐帧适配` is available for placing points in a small frame. Both are view-only; the checkerboard canvas is only a screen background and the PNG remains untouched.
4. The summary displays manually marked head, torso and body-path lengths in source pixels plus head/torso and head/body ratios. These are `MEASURED_SOURCE_PIXELS_ONLY`; absolute body scale remains `NOT_MEASURED` until a valid registration `K` and comparable pose/direction are bound. The common display zoom does not prove equal source sampling density or normalized body size.
5. Save to a new JSON path. Existing output is never overwritten.

The output stores `head`, `torso`, and `body` polylines plus the root anchor in `source_pixels`, with the exact key and image SHA. Keep action poses and facings in separate `pose_group` values when their anatomy paths are not directly comparable.

### Use and interpret the result

Pass the output into the existing `h3.creature.scale-context.v1` file as `landmarks`, and bind the approved reference and actual working registration receipts as needed. A landmarks file without a matching real registration can report only `MEASURED_SOURCE_PIXELS_ONLY`; it cannot pass absolute body scale or compare different sampling densities. A native `K` requires a valid receipt matching the source SHA, native slot geometry, crop, origin and output scale.

This tool records manual points only. It does not identify limbs, characters, pose semantics, art quality, formal 3X status, runtime or game acceptance. The five automatic quality strategies remain diagnostic and keep missing semantic or body evidence as `NOT_MEASURED`.

Run its contract checks with:

```powershell
python -B "$tool\scripts\creature_landmark_annotator.py" --self-test
python -B "$tool\tests\creature_landmark_annotator_contract.py"
```

## Creature master-set normalization and completion audit

> 合并来源：`docs/creature-master-normalization.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

`creature-master-set` audits and derives an isolated scale/layout candidate from pinned high-resolution mother PNGs. It does not call a model, change the input pixels, alter DEF geometry, register native anchors, or approve game use. Candidate output is never the canonical mother set.

The freeze step selects a common effective source scale from the actual alpha-128 subject bounds and each exact native crop. By default it uses the smallest source scale, rounded down to 0.01; this guarantees every output is produced by a uniform downscale or byte-preserving crop, never by enlarging a low-resolution export. The recorded scale remains at least 3x the native crop. Transparent edges are retained with a two-pixel clear margin, and every result preserves the subject aspect ratio. Official duplicates are normalized once and written to each official logical slot as byte-identical aliases.

### Freeze and run a batch

First freeze the exact inventory, current art standard, source PNGs, source hashes, official X3 references, and native geometry into a new manifest. `freeze` writes only that JSON plan. Point `--masters-dir` at an archived set of reviewed source masters:

```powershell
$tool = '{H3TierExport}'
$inv = '{H3-assets}\CompleteOfficialRelease-20261006-v1\codex-map\native-resource-inventory.json.gz'
$official = '{H3-assets}\CompleteOfficialRelease-20261006-v1\OfficialHD2015\manifests\official-hd-x3-selected-extraction-20261020.json'
$standard = '{H3-assets}\CompleteOfficialRelease-20261006-v1\codex-高清母版\批量生图工具\美术标准\town-art-direction-canonical.json'
python -B "$tool\scripts\creature_master_set.py" freeze `
  --inventory $inv --inventory-sha256 (Get-FileHash $inv -Algorithm SHA256).Hash `
  --official-manifest $official --official-manifest-sha256 (Get-FileHash $official -Algorithm SHA256).Hash `
  --identity CGNOLL --faction Fortress --form base `
  --masters-dir '{H3-assets}\CompleteOfficialRelease-20261006-v1\codex-高清母版\生物\要塞\CGNOLL_基础形态\来源母图\pre-normalization-20261025' `
  --art-standard $standard --art-standard-sha256 (Get-FileHash $standard -Algorithm SHA256).Hash `
  --art-standard-version 2026-10-25-r1418-official-slot-count-natural-motion `
  --operation-id CGNOLL-base-normalize-r01 --created-local 2026-10-25 `
  --manifest-out "$tool\build\experiments\creature-master-set\CGNOLL-base-normalize-r01.json"
```

Then run `check`, `run`, and `verify` against the same SHA-pinned manifest. The output must be the new isolated operation directory under the tool's `build/experiments/creature-master-set` root. It cannot be the source mother directory or another canonical art folder:

```powershell
$plan = "$tool\build\experiments\creature-master-set\CGNOLL-base-normalize-r01.json"
$planSha = (Get-FileHash $plan -Algorithm SHA256).Hash
$out = "$tool\build\experiments\creature-master-set\CGNOLL-base-normalize-r01"
H3TierExport.exe creature-master-set check --manifest $plan --manifest-sha256 $planSha --outdir $out --operation-id CGNOLL-base-normalize-r01
H3TierExport.exe creature-master-set run --manifest $plan --manifest-sha256 $planSha --outdir $out --operation-id CGNOLL-base-normalize-r01
H3TierExport.exe creature-master-set verify --manifest $plan --manifest-sha256 $planSha --outdir $out --operation-id CGNOLL-base-normalize-r01 `
  --limb-review '...\提示词\limb-visual-review.json' --limb-review-sha256 REVIEW_SHA
```

The output contains one `DEFNAME_group_frame.png` per logical slot plus a normalization receipt. The tool refuses to write normalized pixels into `codex-高清母版`, a prepared-frame folder, or a 3X output folder. It also refuses to use those typed output folders as its source master set. Normalized candidates are diagnostics for scale/layout; they do not replace source mothers. Preserve the high-resolution model master, then use the formal native pipeline for game assets. `verify` independently replays the resampling from the pinned source pixels, checks aliases, missing/extra slots, exact filenames, alpha margins, dimensions and subject-to-native-crop scale. Source, art-standard, or official-reference drift blocks the batch. It never overwrites sources or an existing slot image.

### Completion report and anatomy review

The completion report checks missing and extra slots, canonical slot names, RGBA/single-frame PNG format, transparent canvas clearance, alpha-128 bounds, and byte-identical aliases. It refuses source directories under `codex-3X`, `codex-prepared`, or `output-3x`. Its `common K` comparison normalizes source sampling density against each exact native crop; it does **not** measure anatomical body size. A common K can coexist with visibly different character sizes when the model drew different subject proportions. Weapons, wings, tails, and pose extension also affect alpha bounds. Treat these bounds as fit/clearance diagnostics, not a body-size pass. Current receipts leave `visual_anatomy_review=REQUIRED`; the planned explicit field should be `body_scale=NOT_MEASURED` unless a pinned category profile supplies anatomy landmarks. The report keeps native canvas/crop/origin registration, exact 3X expansion, native timing, runtime acceptance and deployment as separate false states until the corresponding official pipeline proves them.

Alpha and bounding boxes cannot tell whether a gnoll has exactly two arms and two legs. The tool therefore refuses to infer limb correctness from pixel geometry alone. Supply a separate, hash-pinned visual-review JSON to `verify` after an AI or human has inspected every unique frame class. Its schema is `h3.creature.limb-visual-review.v1`; each item binds `resource`, `output_sha256`, `single_character`, `arms`, `legs`, `tail_present`, `limb_integrity`, and `visual_status`. Missing or failed review remains `VISUAL_REVIEW_REQUIRED` or `BLOCKED`; a pass is reported as an AI/human visual review and never as formal FIT or game approval.

### Size-review features to add

The current completion tool already checks all official slots, names, missing/extra frames, PNG format, alpha clearance, aliases, and common K. A useful document-generation workflow would produce a draft **before** image work and a factual audit **after** the set exists:

1. **Preflight scale-profile document.** Generate `creature-scale-profile-<family>-<revision>.md` from the frozen inventory, current canonical art standard, selected category, and approved reference sample. Auto-fill the identity/form scope, source paths/SHAs, official groups and frame counts, every slot's native canvas/crop/origin, alias classes, and the category name (infantry, mage, mounted unit, large creature, etc.). Leave visual measurements as explicit fields: work-artboard size, target subject occupancy, foot/root anchor, safety margin, and anatomy landmarks. A mounted-unit profile measures rider, mount, and equipment as one composition. If no approved sample or landmarks exist, mark the profile `DRAFT` / `NOT_MEASURED`; do not invent target ratios. The draft document is data for one category/family, not a replacement for the canonical art-standard JSON.
2. **Whole-set scale-audit document.** After preparation, generate `creature-scale-audit-<identity>-<form>-<operation>.md`, covering every official slot and alias with coverage, official filename, source/output SHA, K, alpha bounds, category-profile occupancy, landmark measurements (if supplied), group/pose deviations, and unresolved fields. Show geometry/coverage, sampling density, anatomical scale, formal FIT/3X, runtime, and game status separately. Alpha bounds can flag candidates for review but cannot pass anatomy. Without landmarks/profile, emit `body_scale=NOT_MEASURED`; do not silently substitute alpha bbox.
3. **Common-zoom APNG preview.** `src/apng_gui.hpp::draw_preview` currently fits each frame's full canvas independently. Add a “fit each canvas / same scale for sequence” view mode. In same-scale mode, use `min((viewport_w-24)/max_frame_w, (viewport_h-24)/max_frame_h)` for the selected sequence, keep that pixel zoom for every frame, and label the actual DEF filename/group/frame beside the sequence index. The frame index is only a manual sequence position. This preview improves visual comparison; it does not replace native crop/origin or game review.
4. **Category scale profiles and correction guard.** Pin the accepted reference design and its SHA, family, subject-occupancy diagnostic, foot/root anchor, transparent safety margin, and anatomy-landmark definition. Do not force different families to one height or canvas size; final DEF files retain their exact native geometry. Any body-scale pass or proportional body correction requires hash-pinned anatomy landmarks as defined by the canonical art standard. A proportional correction stays in the qualified preparation path; never edit final 3X PNGs directly.

The profile generator must distinguish values it can read (native slots, file dimensions, K and hashes) from values that need an approved visual reference (category target occupancy and anatomy). The audit generator must preserve that distinction, so a user can see a complete document without the tool manufacturing a scale verdict.

The CGNOLL base review motivating these improvements is recorded in `H3HD/assets/CompleteOfficialRelease-20261006-v1/codex-高清母版/生物/要塞/CGNOLL_基础形态/交接说明-基础狼人-20261024.md`. Its 90/90 files had K values within about 0.61%, while K alone did not establish body-scale equality; the APNG preview's per-frame fit explained the apparent size change in the supplied screenshots. This does not certify every frame's anatomy or game display.

Historical `def_...__<sha>.png` files in the mother directory are listed as legacy source parents, not counted as delivered DEF slots. The normalization output itself uses only the official `DEFNAME_group_frame.png` names. Keep source parents and prior model outputs in the creature's source archive with their path/hash migration receipt.


### Source identity and recovery guard (2026-10-26)

A scale-normalization result is a diagnostic candidate, never a replacement mother image. `creature_master_set.py` / `H3TierExport.exe creature-master-set run` must write only to a new operation folder under `build/experiments/creature-master-set/<operation-id>`; the CLI rejects a canonical mother folder, `codex-prepared`, or `codex-3X` as output. Keep this path guard and its regression test enabled.

Do not use a fixed PNG byte-size threshold as a high-resolution verdict. For source recovery, bind each official slot to an actual model PNG SHA or a source-pinned, 1:1 pixel crop with parent path/SHA and crop rectangle. One-frame masters can be smaller than their full-canvas source because transparent margins and PNG compression vary. A multi-pose raw sheet remains source evidence; it cannot be installed as one DEF frame. Before replacing a current master, record its SHA, move it to a new unique `{H3-workspace}\待删除` batch, restore only from a verified source, and write a separate restoration receipt. Never rewrite an old normalization receipt as if its output were still current.
