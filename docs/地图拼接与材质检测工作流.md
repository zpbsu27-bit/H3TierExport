# 地图拼接与材质检测工作流

汇总道路、河流、地面材质、原生地图格装配和地图对象母版规则。地图编辑器邻接、原生 alpha/几何、实际 3X 端口、材质边界与画面检查分别记录；不能用单一图像指标替代完整场景验证。

## 统一操作约束

- 每批任务使用唯一 operation ID，冻结来源路径、像素尺寸、SHA、原生槽位和实际算法版本。
- `check` 不写素材；`run` 只写新隔离目录；`verify` 从冻结输入重算并核对输出。
- 原始高清母版、处理候选和正式 3X 交付分开管理；不把低倍率输出升格为母版。
- 报告中的 `PASS` 只对其明确列出的合同负责；艺术身份、实际地图拼接和游戏运行需分别核验。

## 道路系列：画前辅助与拼缝经验（2026-11-02）

用户确认的 COBBRD 画风是：**路面中央有较大的立体石块和细碎石，两侧有清晰可见、相对较小的路肩石子**。保持已确认参考的欧美写实奇幻 2.5D 风格、石块形状、色调和路肩样式，只为宽度一致及接缝吻合做必要调整；保留透明底、自然的细微轮廓起伏。直路、弯道、路口和尽头同系列色调与材质一致。避免毛刺过多，也不把边缘磨成光滑刀切；两侧及弯道内侧的路肩不能缺失或因拼接变虚线。用户确认的是风格方向，不等同于现有试样整套美术验收通过。

先依据 2015 官方 HD 3X 的轮廓和走势，设计各类道路各自的描点、中心线、统一宽度与共同接口。官方 1X 用于识别原生槽位和真实几何，不将其像素 Alpha 放大为最终高清轮廓。先将整系列形状按合法邻接组成预览，修正直线、曲线、T 口、十字、尽头及四格交点，再逐张生成透明原图。不同道路系列的宽度目标应一致，颜色和材质可以不同；实际目标需按当前素材及裁片审核，不把某次试验的 30 像素硬编码为永久标准。

**可以用来辅助生图，而不仅是画后检测：**

- `scale-layout quality-init` 的道路类档案会生成 `generation-brief.md`，新版新建档案纳入上述系列画前要求；COBBRD 的大小石子要求只作用于 COBBRD。按用户选择冻结高清风格参考路径和 SHA，再将简报及逐槽参考交给生图工具。旧档案不自动改写，以免破坏冻结回放。
- 新建道路档案可在 `production-profile.json` 的 `road_drawing_guides` 填入逐槽参考，条目形如 `{"key":["def","COBBRD",0,1],"role":"geometry","source":{"path":"绝对PNG路径","sha256":"文件SHA256"}}`；`role` 可为 `geometry` 或 `style`，同一槽同一角色只能一条。简报生成时核查槽位属于档案、PNG 格式及实际 SHA。改图须重新绑定 SHA 并重新冻结；旧档案不自动获得此字段。路径和简报供当前制图人员或有此功能的适配器明确提交，现有代码不自动上传图片、不调用生图模型。
- 可用 `scale-layout road-generation-packet --profile PROFILE --profile-sha256 SHA --output-root 绝对候选目录 --out 新任务JSON` 为档案中的每个道路槽生成一条网页批量任务，要求每槽各有一张已冻结的 `geometry` 和 `style` PNG。生成前重新核对档案身份、规范版本及 SHA、原生 inventory 的 SHA 和槽位存在性，任一漂移或缺槽则阻断。输出只含 `tasks` 等准备信息，不启动浏览器或生图；网页批量器可用 `--tasks-config 新任务JSON` 读取它，配置好 provider 并由用户发起任务后才会上传这两张参考。`expected_reference_sha256` 在任务读取时校验，原有提交前复查继续生效；不能改图后沿用旧 SHA。H3TierExport 1.3.31 发行回执中，road-generation-packet 的单任务准备测试通过；这只证明任务准备，未证明上传或生图。网页批量器对参考 SHA 的实际提交前校验须按其当前版本单独核验。
- `tile-design` 可依据明确的功能轮廓、原生裁片和开口输出画前几何参考；`tile-interface` 可制作中性布局参考与来源固定的彩绘接口构件。它们辅助人和生图模型理解形状，不是模型内的硬约束，也不是合格母版。
- 真实高清原图及来源不变；在独立处理层中依据固定坐标和两轴接口合同装配，再由正式采样器采样 3X。原画中可复用的形状可做无插值旋转或整格镜像，但仍按目标槽位自己的 crop/origin 注册并查方向与裁切；游戏运行时只使用消费者实际支持的镜像。不能拉伸石头、放大旧像素蒙版、模糊接缝或将处理结果倒灌成原始母版。

**这些仍需检测和真实画面复核：** 宽度与中心位置、方向、真实 Alpha、接口逐像素及多行过渡、颜色和颗粒变化、重复镜像纹样、两侧路肩、内弯及正常游戏尺度的视觉效果。固定公共接口如果从大石中间镜像，可能出现“双翼”重复；即使接口边缘 RGBA 完全一致，内部仍可能有贴条、台阶或色差。接口与轮廓数值只能给技术诊断，不能自动证明自然或美术通过。

源码模型中的 680 个合法配对与 2,888 个保守压力配对分别统计，后者不是游戏实际合法配对数。完整 Qt 编辑器离屏显示可用于不占桌面的实显审阅；其结果与用户桌面可见显示、实际游戏运行分别记录。任何未执行项记 `NOT_MEASURED` 或 `REVIEW_REQUIRED`，不因其他项通过而推断通过。提示词、参考和检测都不能保证 AI 对描点像素级服从。

## 原生地图格与道路3X装配检查

> 合并来源：`MAP-ASSEMBLY.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

当前命令从既有入口调用：

```
H3TierExport.exe scale-layout map-fixture --spec SPEC.json --spec-sha256 SHA --outdir NEW_EXPERIMENT --operation-id ID
H3TierExport.exe scale-layout map-review --spec SCENE.json --spec-sha256 SHA --outdir NEW_EXPERIMENT --operation-id ID
H3TierExport.exe scale-layout map-source-proof --spec SOURCES.json --spec-sha256 SHA --outdir NEW_EXPERIMENT --operation-id ID --cxx PINNED_COMPILER
H3TierExport.exe scale-layout road-batch-register-model --editor-proof PROOF.json --editor-proof-sha256 SHA
H3TierExport.exe scale-layout road-batch-freeze --inventory INVENTORY.json.gz --inventory-sha256 SHA --identity COBBRD --sampling-run RUN.json --sampling-run-sha256 SHA --operation-id ID
H3TierExport.exe scale-layout road-batch-run --manifest MANIFEST.json --manifest-sha256 SHA --outdir NEW_EXPERIMENT --operation-id ID
```

源码入口：`scripts/subject_scale_layout.py`、`scripts/map_assembly.py`。发布前必须重新构建并通过产品测试；旧EXE不因为文档更新便具有新入口。

输入绑定实际H3M文件SHA、解压正文SHA、地图头尺寸与层数、已核实的地形表偏移及表SHA。地形表严格按 `[层][行][列][7字节]` 读取；不是通用H3M头解析器，不能猜测表位置。每格显式使用地图保存的资源类型、帧号与镜像位。

`actual3x` 为官方槽位键、现有3X道路/河流裁片路径与SHA、真实母版来源与SHA、采样证据及角色声明。按官方canvas/crop/origin在内存注册，不缩放裁片；道路画布相对地图格向下偏移48个3X像素。`actual3x_layers` 可要求道路和/或河流显示正式3X，省略时为兼容旧场景默认只显示道路3X；报告分别列道路、河流缺图、相邻检查与实帧数。绘制地形/河流/道路，提供网格、帧号与原版参考切换。当前不渲染物体、迷雾或游戏逻辑。

地图编辑器保存的 SoD 版本28、无玩家道路布局可用 `H3HD/tools/map_editor_h3m_review.py inspect` 生成布局证明，再用 `scene-spec` 绑定当前正式3X库。它按已钉住的 VCMI H3M 读取顺序解析表偏移，不扫描字节猜位置。场景报告按编辑器实际道路/河流格回放，并把正式3X道路和河流材质画回同一网格；这证明布局和本地绘制结果，不等于正式游戏运行验收。

检查页嵌入现有像素，不新增PNG、母版或游戏资源。底图若来自原版1X，明确标记为参考显示；缺高清道路用明显缺失提示，不悄悄回退再计入通过。

`road-connection` 类别将模型、实际3X接口、合法邻接、地图场景与材质接缝分别列项。没有完整图集与源绑定的共享接口合同就保留 `NOT_MEASURED`。当前接缝Alpha/RGB数值为诊断，不能代替合成画面检查。

研究与完整源码下载回执见 H3 工程 `H3HD/docs/map-editor-assembly-20261026-r01/README.md`。后续优先离屏测试，不接管用户鼠标键盘，也不改现有编辑器/游戏文件。

`scripts/road_batch_quality.py` 是批量自动入口，提供冻结、只读检查、运行和复验。登记模型采用当前文件SHA的CAS；旧模型记录只移入新审核批次。模型更新后的重新核对使用既有固定源码和编译器，原版输入有漂移时拒绝自愈。

全17槽从inventory取得；3X PNG、采样回执、任务指纹、RGBA哈希和高清父图分别绑定。逐槽检查开口与分支连通；按源模型枚举所有合法配对。共享接口必须有 `h3.road-painted-interface.v1` 合同，绑定真实彩绘构件回执、实际3X参照和检查带深度。构件须由原始高清父图的整数ROI和像素置换重放一致，透明像素隐藏RGB不作为可见色差；不同道路材质各用各的合同。没有合格彩绘接口就保持未测量，不用灰色测试构件冒充。

工具现提供 `tile-interface roi-layer`：用约分整数比 `pixels_per_native_ratio=[N,D]` 将真实高清父图映射到原生格，自动计算半像素边界包络与偏移，输出带母图SHA、原生矩形和有理边界的图层记录；不先缩放/拉伸父图，最终仅由H3TierExport采样器直接产出官方3X裁片。对1254×1254映射32×32的输入可用 `[627,16]`；任何画布尺寸、源SHA、原生槽位或裁片合同不符都会在写图前阻断。

此采样能力只解决注册精度，不能单独证明道路接缝通过。共享彩绘接口仍需真实父图来源、明确构件坐标、所有槽位3X、VCMI合法邻接组合与地图合成实测；未完成时继续报告 `NOT_MEASURED`，不得将单张3X或格式通过升格为整组拼接通过。

## 开画前的瓦片几何与实际3X采样验证

> 合并来源：`TILE-GEOMETRY-DESIGN.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

`tile-design` 在绘画之前制作平滑的几何模板和显式测试纹理。原生Alpha只作几何证据，原版RGB不进入测试画面；不会把旧画面拉伸、挤出或模糊来对接。输出明确为 `NEUTRAL_GEOMETRY_FIXTURE_NOT_ART_MASTER`，不能入高清母版或计作重绘完成。

输入 `h3.tile-geometry.design-manifest.v1` 逐项绑定原生参考SHA、逻辑canvas/crop/origin、功能开口与公共开口区间，显式选择工作密度、接口纵深和轮廓平滑次数。先对几何锁定端口，再平滑单元并集的矢量边界，以像素中心扫描转换输出带抗锯齿的工作模板。若设计超出原生crop，直接阻断，不靠事后裁图掩盖。

```text
H3TierExport.exe tile-design check --manifest ... --manifest-sha256 ... --outdir ... --operation-id ...
H3TierExport.exe tile-design run --manifest ... --manifest-sha256 ... --outdir ... --operation-id ...
H3TierExport.exe tile-design verify --manifest ... --manifest-sha256 ... --outdir ... --operation-id ...
```

输出只允许工具 `build/experiments/tile-geometry/<operation-id>` 新目录。check不落图；run不覆盖；verify根据原始SHA、算法SHA和像素／轮廓诊断重放。所有可见RGB是清晰的二维坐标测试标记，公共接口的反转兼容来自预先设计的对称坐标函数，不是对两张画面求平均。

实际3X由既有正式 `motion-plan / motion-run / motion-verify` 采样器输出。业务适配器只能提供均匀源ROI到原生crop的映射和原生槽位，不应将局部变形伪装成这类几何试验。

```text
H3TierExport.exe tile-sampling-proof --context ... --context-sha256 ... --run ... --run-sha256 ... --out NEW.json
```

采样证明读取真正的PNG裁片与采样回执，恢复 `origin×3`，检查全部功能口在四种翻转下的相对组合、完整RGBA、接口内三行／列、内部连通，以及声明的半格消费者坐标模拟。不同原版口宽也不能被提前过滤掉。报告不落预览图，不改图，不宣称正常美术、静止层／动画、游戏Hook或实际场景已通过。

当前上下半格参考投影使用显式 `consumer_projection` 参数，适用于声明了该规则的消费者。其他投影暂不支持，必须另行接入和验证，不能照搬到所有图类。

生产仍须独立处理真实高清材质／组件、模板与内部画面匹配、非接口裁切、图层和实际消费。几何测试通过只说明该声明的几何与采样原型成立。

本版同时修正既有类别报告的缺证据边界：旗帜缺目标或测量带、测量带没有旗杆时为NOT_MEASURED，不能根据bbox猜旗杆；船只需源SHA绑定的物理水线锚点和明确宽度参照，轮廓底部不能代替水线，宽度代理不能被称为三维体积通过。这些是只读报告修正，不更改现有图像或质量阈值。

## Shared terrain material families (1.3.7)

> 合并来源：`TERRAIN-TEXTURE-FAMILIES.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

`asset-repair` operator `registered-terrain-family` builds opaque native32 centre variants from one receipt-bound genuine HQ painting. It accepts registered editing scales16..32 only. Existing source pin, native inventory, family, crop/origin and output-root checks remain mandatory. It never imports native RGB or promotes3X into a master.

The reusable implementation is `scripts/terrain_texture_core.py` plus `scripts/asset_repair_terrain.py`. Painting is assembled from full two-dimensional source patches. Minimum-error seams select complete source pixels; there is no RGB averaging, one-row extrusion, blur, scaling or alpha fade. Seeded interiors differ. A genuine painted quadrant supplies a shared mirrored boundary template, with bounded variable seam positions. Horizontal/vertical flips share the same profiles. This proves a boundary property, not natural appearance or game acceptance; repeated motifs and interior cuts still require inspection at actual3X.

Optional per-slot accents use a separate registered HQ painting and explicit owner-supplied RGB seed ranges. Connected feature components are protected, and surrounding painted patches join along minimum-error cuts. Seed pixels are retained exactly; the fixed outer boundary remains unchanged. Boundary exclusion, discarded seeds and patch regions are reported. Empty declared accents are blocked. The software cannot infer whether a crack, plant or soil mark is semantically correct.

Each family contract pins its real native inventory, parent native key, material identity and exact target key list. Variants declare IDs, native keys, seeds and optional accent bindings. Job parameters are `frame_native`, `patch_native`, `overlap_native`. Results contain per-variant diagnostics, output geometry and replayable source chains; no automatic art, complete legal-map adjacency or runtime approval is emitted.

Patch synthesis follows the minimum-error patch-joining approach described by [Efros and Freeman, Image Quilting, SIGGRAPH2001](https://people.eecs.berkeley.edu/~efros/research/quilting.html). The shared H/V boundary contract and slot-bound accent handling are this tool's additional constraints. Taking unrelated windows from a common parent alone does not guarantee arbitrary game-selected neighbors.

Use this operator for homogeneous material centres with owner-verified roles. Cross-terrain transitions, water palette animation, roads/river throats and dynamic coastlines require their own native consumer contracts. Full-canvas Alpha255 is not evidence of correct material boundaries. H3-specific mappings, source selections and approval records stay in the H3 adapter and are not embedded as special cases here.

## 地图宝物母版整备

> 合并来源：`docs/map-artifact-master.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

`map-artifact-check`、`map-artifact-export`、`map-artifact-verify` 是同一 EXE 内的原生功能。输入冻结的 `h3.map-artifact-master-manifest.v1` 清单，命令参数均为 `--manifest PATH --manifest-sha256 SHA --outdir DIRECTORY`；可用 `--report NEW.json` 保存回执。

源图必须是带真实 Alpha 的 AI 母图。主体只作等比缩放及平移，保留全部正 Alpha 内容；官方物体外接矩形只决定可用范围和落脚点，不能用于分别拉伸宽、高。源图直接经过现有线性光、预乘 Alpha、Lanczos3 / EWA 和防振铃质量管线，PNG 无损保存，ICC 色彩按既有 WIC 合同处理。工具不调整饱和度或统一加灰。

投影先测量本槽位官方参考帧的落影重心、方向和透明度，再从高清主体 Alpha 做平面投影与高斯近似平滑；不放大原版的锯齿阴影，也不使用上下镜像倒影。有官方 HD PAK 独立阴影层且尺寸严格等于原生裁片乘参考倍率时，可用该层取得更准确的重心，保留原点注册。投影严格限制在原生裁片中，记录仿射参数、重心、平滑半径和透明度。动画使用完整官方帧序列锁定主体范围，按各帧的实际明暗变化提取闪星位置。

清单同时钉住官方对象表、官方库存、DEF 二进制、原始帧 PNG、AI 源图及动画序列的 SHA-256。对象表普通宝物的 subtype 对应 `ARTIFACT.DEF` 帧号，不能用 `AVA` 文件序号减一来替代；法术卷轴是 type 93/subtype 0，对应背包帧 1；潘多拉是 type 6/subtype 0，源图属于地图专用母图。工具从 DEF 二进制重读真实组帧几何，拒绝源图漂移、身份错配、原生几何漂移、重名输出和不透明背景源图。

原生 LOD 里存在、对象表里没有引用的历史图形，必须显式使用地图专用 AI 母图并保留身份审查记录，不能编造一个对象表编号。已有对象表绑定的资源不能走这个入口绕过身份核对。

五张官方文字占位 `AVA0003/0004/0142/0143/0144` 使用单独的 `official-placeholder` 路径：只接受与该槽官方 PNG 完全相同的已钉住来源，按整数像素格保持原文字、方块和透明区域，输出正式同名占位图。它们明确记为官方占位，不冒称 AI 重绘；不得用无关宝物填充。这个入口不能用于普通宝物或绕过普通 AI 母图的透明背景要求。

输出为高分辨率母版候选，保存官方资源文件名、主体缩放量、官方投影方向、源图与输出哈希及实际质量算法。`verify` 独立重放并核对 PNG/RGBA。工具回执只证明技术处理，不替代身份和画面的实际检查，不修改游戏客户端。
