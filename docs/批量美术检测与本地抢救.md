# 批量美术检测与本地抢救

汇总制作前档案、制作后批检、本地抢救算子和算法采用边界。所有操作先冻结来源与 SHA，再按 check → run → verify 生成隔离候选；技术通过不等于艺术或游戏验收。

## 统一操作约束

- 每批任务使用唯一 operation ID，冻结来源路径、像素尺寸、SHA、原生槽位和实际算法版本。
- `check` 不写素材；`run` 只写新隔离目录；`verify` 从冻结输入重算并核对输出。
- 原始高清母版、处理候选和正式 3X 交付分开管理；不把低倍率输出升格为母版。
- 报告中的 `PASS` 只对其明确列出的合同负责；艺术身份、实际地图拼接和游戏运行需分别核验。

## 动态序列的强制尺度与帧完整门（1.3.56）

对“静止建筑/地图底图 + 水、烟、火焰、旗帜等逐帧效果”的序列，扩级计划必须选 `static-structure-dynamic-fx-v2`，并绑定官方原版 1X 帧目录。工具在计划冻结时枚举 `<身份>/<组_帧>.png` 官方帧清单，记录文件名、像素尺寸与 SHA；`expand-check`、`expand`、`expand-verify` 会再次核对这份清单和来源帧集合。官方帧缺失、来源漏帧、额外帧、参考目录变化、少于两帧或空帧都会阻断。

多帧组必须显式分类。扩级核心会识别相同身份下同一 `<组>_<帧>.png` 前缀的多个来源帧；未指定动画合同或独立静态帧目录就阻断，即使各帧的 Alpha 外框完全一致或整张不透明，也不会当作静态单图放行。若来源只列首帧、但绑定的官方目录已有多个同组帧，也会阻断。`single-or-unrelated-v1` 只用于互不相关的单张图，不能豁免同组多帧。

逐帧独立绘制但仍需校验完整原生帧目录时，明确选择 `independent-static-frame-catalog-v1`。它固定官方 1X 帧名、尺寸和 SHA，并逐帧绑定原生画布；每张独立扩展，不要求静态像素共享，不启用动态 FX 包络检查。静态结构+FX 使用 `static-structure-dynamic-fx-v2`。VCMI BASE 动画新批次使用 `static-base-dynamic-overlay-v2`：官方 frame0+current-frame 合成作为基线，来源固定像素比例不得比官方低超过 5 个百分点，更稳定的底图允许，每帧 FX 绝对尺寸、中心锚点对照对应官方帧不超过 5%。官方本身变化范围很大的完整云层、烟雾、火焰帧可以通过；额外闪烁、尺寸跳变、位置漂移会阻断。v1 保留给历史批次复验。

当用户明确指定“固定底盘 + 自定义动效区域”时，使用 `static-base-authored-fx-roi-v1` 并传入同画布灰度 ROI PNG。计划冻结 ROI 路径与 SHA；执行门按 VCMI BASE 合成检查完整官方帧、画面几何、ROI 外底图静止、ROI 内尺寸/锚点变化和帧间平均亮度。效果只允许在 ROI 内动；超出 ROI 的像素变化、亮度脉冲、覆盖面积呼吸或锚点漂移会阻断。该合同用于有明确美术意图的自定义动画，例如固定尾盘后只旋转顶部云层；不作为绕过 `static-base-dynamic-overlay-v2` 原生 FX 尺寸比较的通用例外。

整组扩级使用一个共享均匀变换，把来源帧可见联合包围 fit 到官方序列联合包围，并将同一个变换用于所有帧。门禁在该变换下核每帧尺寸/比例和组内倍率跨度（容差 5%），避免逐帧 bbox-fit 造成静态本体呼吸。底图必须在整组帧中共享至少 20% 完全一致 RGBA 可见像素；否则先拆成共同底图层与逐帧动态层。动态 FX 的帧间宽/高变化幅度按官方整组自然变化量比较；母版额外变化超过 5 个百分点，或组均值 FX 锚点偏差超过画布的 5%时阻断。官方本身烟雾、翅膀、水流的变化按对应序列保留，不把有意变化误判为尺寸错误。报告输出官方帧清单、共享变换、投影框、倍率、静态层覆盖、FX 变化幅度和原因码。

该门检查几何和时序变化，不判断某种烟雾/火焰的尺寸变化是否属于有意设计。若动画本身确实需要改变效果包围范围，应先停下并定义经审核的动画合同；当前门禁没有静默豁免。不要为了让报告通过而删减官方帧或把画面缩进透明边。

### VCMI BASE 静态底图复用与动态叠层（`static-base-dynamic-overlay-v1`）

本机 VCMI `client/windows/CCastleInterface.cpp` 中 `CBuildingRect` 使用 `CShowableAnim::BASE`；`client/widgets/Images.cpp` 的 `CShowableAnim::show()` 先绘制 `first` 再绘制当前 `frame`。仅当消费者具有该语义时才使用此合同。frame 0 保存完整静态建筑与初始旗；frame 1..N 保存旗帜等动态叠层。几何门在内存审核副本中按相同 source-over 顺序合成 source 和官方 1X 帧；静态底图门以 frame 0 原图为基准，对照后续合成场景，避免首帧自身重复绘制造成的轻微 Alpha 变化被计为房体运动。动态 FX 的幅度与锚点只比较 frame 1..N 的 overlay 和官方对应 overlay。输入 PNG 不改写，输出仍为完整 `canvas×3`。合同绑定 `static-base-dynamic-overlay-v1` 与 gate schema，不替换 v2，也不能用于逐帧独立绘制。

## 本地素材抢救与可迭代派生（1.3.2）

> 合并来源：`LOCAL-ASSET-REPAIR.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

正式入口：`H3TierExport.exe asset-repair`，或程序“批量任务中心 → 本地素材抢救与派生 asset-repair”。此模块属于工具产品，项目脚本只负责原版资料、槽位和参数绑定，不复制图像处理算法。

### 当前算子

| 算子／版本 | 用途 | 强约束 |
|---|---|---|
| `shared-interface-collar / 1` | 同组共享高清接口材质，修复接触带宽度／透明差异 | 当前只接受32×32原生画布、相同编辑倍率、同身份材质父图和显式接口边；接触带外核心逐字节不变 |
| `registered-parent-reslice / 1` | 同一注册高清整图按原生矩形和alpha切成碎片 | 全部片共用父坐标；RGB不重采样；每片必须绑定自己的原生身份和crop/origin |
| `registered-alpha / 1` | 用原生逻辑alpha限制高精图的透明范围 | 原版RGB不进入绘画；默认相交，不允许replace揭示全透明的无绘画像素 |
| `masked-color-variants / 1` | 局部OKLCh颜色变体 | Alpha和蒙版外像素精确不变，输出原尺寸 |
| `locked-rgb-flow / 1` | 静止岸线／底座内的周期RGB水流 | Alpha和非水面像素精确不变，偏移不能采到透明区域；不宣称官方动画时序 |
| `native-canvas-assembly / 1` | 将正式工具的3X裁片按原生原点贴回完整3X画布 | 必须是target_scale 3回执；不缩放RGB，不转为高清母版 |
| `material-lab-harmonize / 1` | 同材质区域的温和Lab对齐 | 显式材质蒙版＋同家族真实高精参照；亮度和色度位移分别限幅，不抹平中心植被，不自动判重绘 |
| `locked-static-base / 1` | 多张已有高精帧共用静止层 | 帧图必须共享原生注册；动态蒙版外RGBA及全幅Alpha精确锁定，每帧测量静止差值 |
| `bounded-key-decontaminate / 1` | 已确认背景色的连通外背景／边缘去污 | 必须有显式污染蒙版；检查外背景连通性或有限边缘距离；不按青色本身判污染，不跨图边取色 |
| `checkerboard-alpha / 1` | Gemini 把透明背景画成浅灰/深灰棋盘格时，识别周期背景并输出透明 PNG | 仅接受边缘样本确认的中性双颜色周期棋盘格；仅透明化边缘连通背景，邻主体混色像素有限反混；原图不覆盖，图案不确定即拒绝 |
| `material-label-diagnostic / 1` | 比较已分类的地表材质位置和接口带 | 使用绑定绘画源的材质ID数据；记录缺失材质、未知区、四边错位；不把光照相关性当边界掩码 |
| `coordinate-state-effects / 1` | 同形状征服斜线与原生选中描边 | 斜线共用世界坐标相位；状态几何／Alpha逐项绑定，不猜按钮状态数和按下位移 |

原生重新注册继续复用正式`motion-plan/check/run/verify`，不新增另一套倍率导出器。抢救输出是**有来源链的高清候选**，不是新模型原图，也不是自动批准的正式3X。最终3X仍需整批核验，再使用所属正式原生几何导出入口。

### 任务协议

清单schema为`h3.asset-repair.manifest.v1`。所有图片、蒙版、上游回执均需绝对路径和SHA；图片另需实际像素。原生几何字段统一为`canvas_1x/crop_1x/origin_1x`。

```json
{
  "schema": "h3.asset-repair.manifest.v1",
  "operation_id": "road-interfaces-r01",
  "jobs": [{
    "id": "TRDD030",
    "operator": "shared-interface-collar",
    "operator_version": 1,
    "native_key": ["def", "DIRTRD", 0, 10],
    "source": {
      "image": {"path": "ABSOLUTE_REGISTERED_HQ_CROP.png", "sha256": "SHA", "pixels": [448,1024]},
      "receipt": {"path": "ABSOLUTE_MOTION_RECEIPT.json", "sha256": "SHA"},
      "geometry": {"canvas_1x":[32,32],"crop_1x":[14,32],"origin_1x":[9,0]},
      "editing_scale": 32
    },
    "material": {"image":"同结构的已注册同组高精父图绑定","receipt":"回执绑定","geometry":"原生几何","editing_scale":32},
    "native_mask": {
      "path": "ABSOLUTE_NATIVE_GEOMETRY.png", "sha256": "SHA", "pixels":[32,32],
      "data_role":"native-logical-alpha-geometry", "alpha_sha256":"SHA_OF_ALPHA_BYTES",
      "native_key":["def","DIRTRD",0,10],
      "native_geometry":{"canvas_1x":[32,32],"crop_1x":[14,32],"origin_1x":[9,0]}
    },
    "controlled_sides":["top","bottom","left","right"],
    "depth_native":3,
    "shared_native":1
  }]
}
```

上例仅说明结构，`material`中的说明字符串必须由实际绑定对象替换，不能原样运行。项目适配器负责自动生成真实任务，不让用户手填几十张图的几何。

`source`必须引用高精`motion`注册回执或上一次`asset-repair`回执，且PNG的SHA、实际crop、倍率、原点、身份都匹配。禁止把target scale 3的导出片作为高清抢救母版重新升格。只有明确的`native-canvas-assembly`交付算子接受3X裁片，其结果始终标为3X交付数据，不能作为高精修复源继续升格。工具会继续核对上游绘画文件的SHA和像素；原始生成来源的艺术／身份资格仍归生产owner核实，工具不会因为文件大就批准。

`registered-parent-reslice`的每个`parts`条目含`id/native_key/target_geometry/rect_native/mask`；mask为相应crop的逻辑alpha。`masked-color-variants`使用同尺寸的`selection-weight-mask`，红通道乘alpha作为权重，`variants`指定`id/hue_degrees/chroma/lightness_offset`。`locked-rgb-flow`用同类权重蒙版，参数为`frames/amplitude_pixels/direction`。

裁片mask另绑定`native_key/native_geometry`。空parts拒绝执行。默认裁片任务仅表示局部裁切；需要证明完整覆盖时，同时提供`required_part_ids`和父画布尺寸的`expected_coverage_mask`。缺槽、空覆盖或所需父像素未覆盖会被拦截，不能用“只比较已经覆盖的部分”证明整图拼好。

#### 吸收分级套件后的新增参数

- `material-lab-harmonize`：`material_id/mask/references`必填。每个reference为`native_key/source/mask/material_id`，source沿用高精注册绑定，mask为显式`selection-weight-mask`。参照材质区域的Lab均值取中位值；采用70%阻尼位移，`max_lightness_shift`默认4（上限6），`max_chroma_shift`默认4（上限8）。保留纹理和蒙版外像素。残差大只写入指标，不凭14一类经验阈值宣告必须重绘。
- `locked-static-base`：source是共同静止父图，`mask`只定义可变RGB区域，`frames`每项为`id/native_key/source`。原生组、几何和编辑倍率必须一致；蒙版外逐字节保持共同父图，全幅Alpha也不跟随分帧变化。不同裁片／原点需先准备合法共同坐标，不能隐式resize。
- `bounded-key-decontaminate`：`mask/key_rgb`必填。`mode=fringe-rgb`默认仅从同一图中有限距离的干净邻点修复RGB，Alpha不变；`radius_pixels=1..8`，按实际高精像素计。`mode=exterior-key`只移除与画布边缘连通且明确选中的背景色；主体内孤立同色像素不得移除。深层污染或缺少可靠邻点时阻断，不自动判重绘。
- `material-label-diagnostic`：输入`native_reference/native_labels/candidate_labels/labels`。两份label PNG是**材质ID数据**，不是绘画：红通道为ID，Alpha必须255，0表示未知。引用需写`data_role=material-label-data/native_key/native_geometry/coordinate_scale/source_sha256`；native为1X数据，candidate与source编辑倍率一致。`labels`每项为`id/material_id`。输出只有诊断回执，无图片，也无自动合格／重绘判断。分类准确性和合法场景仍由owner核实。
- `coordinate-state-effects`：`base_mask/mask/states`必填。source必须已按原生base alpha形成区域，不能把整张不透明背景当区域。每个state绑定`id/native_key/geometry/native_mask/mode`，几何必须共享。`mode=hatch`还需`coordinate_origin_native`，斜线周期与宽度按native单位；选中描边`mode=outline`需`outline_rgb`，允许扩出的范围严格由原生状态mask决定（最多声明1–2个native像素的轮廓带）。绘画结构不同的状态不由本算子猜造。

`checkerboard-alpha` 是独立的图像背景处理入口，不属于已注册原生素材的 `asset-repair` manifest：主界面“棋盘格转透明…”可多选同一文件夹中的 PNG。工具从图像边缘估计两种中性格色、格子周期与相位，周期置信度未达门限就拒绝输出；确认后仅将与画布边缘连通的背景像素写为 Alpha=0，并对紧邻主体的混色边缘做有限反混。输入图不覆盖，候选写入新的 `Gemini-transparent-*` 目录并记录来源/输出SHA、格子周期及透明像素数。主体内部绘制的棋盘纹理不自动擦除，仍需拒收或定向重绘。

### 检查、运行、复验

```text
H3TierExport.exe asset-repair catalog
H3TierExport.exe asset-repair check --manifest ABSOLUTE.json --manifest-sha256 SHA --operation-id road-interfaces-r01 --outdir PRODUCT/build/experiments/asset-repair/road-interfaces-r01
H3TierExport.exe asset-repair run    --manifest ABSOLUTE.json --manifest-sha256 SHA --operation-id road-interfaces-r01 --outdir PRODUCT/build/experiments/asset-repair/road-interfaces-r01
H3TierExport.exe asset-repair verify --manifest ABSOLUTE.json --manifest-sha256 SHA --operation-id road-interfaces-r01 --outdir PRODUCT/build/experiments/asset-repair/road-interfaces-r01
```

`PRODUCT`需换成工具目录的绝对路径。CLI包装器自动绑定当前EXE，不允许调用者覆盖renderer。可显式指定已有`--python`，不要求固定CDP或账号。

- `check`核对整批输入并计算算子条件，不写图片。
- `run`仅写工具专属的新operation目录。既有外来／失败半成品目录不能覆盖；相同完整任务重跑时执行verify。
- `verify`重新从输入计算像素，核对输出文件SHA和RGBA，能发现修改／丢失输出。
- 诊断指标也逐项重算比对，不能手改“抖动=0”或其他统计后继续通过。
- 不改输入PNG，不自动修改正式母版、原生索引、DEF／LOD或客户端。
- 单任务和整批有输出容量限制；超过时拆成小批，不放宽来源、透明或几何检查。

### 迭代而非一次性修图

更改参数或算法版本时创建新operation和新清单。旧任务与回执保留，结果不能静默覆盖。新任务可把上次抢救输出及其回执作为源，保留原生身份、几何和原始绘画来源链。

每个算子有独立版本。增加新修复类型须有真实缺陷样本和回归测试，不为某张图放宽全局门禁。测试覆盖输入漂移、错误原生槽、输出越界、重复任务、禁止低倍率升格、静止像素不变、同父图裁片和像素重放；产品整套资格测试同时运行本模块。

河流必须显式区分水道出口与河岸擦边；`controlled_sides`是消费关系数据，算子不猜。开口修好了也不证明整组拓扑、画面或实机已通过。棋盘格混入主体、真正缺失的分支和错误身份不能通过改Alpha伪装修好。

R8占格／身份检查沿用工具已有`native-review`和原生合同入口：Alpha外框只作为FIT诊断，不代替战场六角阻挡表、地图对象访问格或身份审查。算法吸收的取舍与反例见`ALGORITHM-ADOPTION-20261025.md`。

### 对应抢救分级

- 留白／原点错：先走原生注册，再派生；不是居中放大。
- 接口宽位差：共享接口候选＋合法邻接回归；不改动整个主体。
- 岸线跳动：同父图＋锁底座水流，保留非水面精确像素。
- 谜图／领土错位：同父图坐标裁片＋颜色状态，禁止各片单独contain。
- 地表一格一色：同组材质与区域颜色处理仍需合法铺图；本模块不自动宣称任意地形无缝。
- 棋盘格／青边：明确的几何透明处理只去可分离污染；不能恢复缺失的真实绘画。
- 身份／结构错：先检查注册，无法抢救时才定向补绘。工具不会凭输入齐全自动批准美术。

### 原始高清接口截面注册（2026-10-26）

旧 shared-interface-collar 会对镜像 RGB 取平均并替换宽边带，不能用于用户指出的道路/河流拖影返工。新模块 `scripts/interface_port_geometry.py` 提供 `initial_roi`、`rectangular_registration`、`validate_formal_mesh` 和 `reorient_rgba`：只从真实高清源测量连续不透明截面，显式裁掉端部渐隐，再让既有 motion 原生采样器做完整二维网格注册；不重复一列/一行、合成宽模糊带或把原生 Alpha 网格放大为绘画。

截面必须在二维带内连续，不能以两岸的不透明像素包围盒冒充中间有水。保留的 ROI 必须完整进入网格；既有所有 Alpha>0 覆盖检查、原生 crop/origin、三角形面积变化及边长比例上限全部保留。目标开口的源端点向不透明区内收 0.1 个原生尺度，仅改变真实二维纹理的取样位置，给实际3X重建滤波留出空间，不描边或改变源 Alpha。

本模块返回可冻结的坐标，图像重采样仍由正式 H3TierExport motion-plan/run/verify 执行。H3 项目适配器 `H3HD/tools/rework_map_opaque_ports.py` 负责真实 DEF/原生库存/功能口、来源 SHA、整批预检和同材质父图关系。直线的90度调整是无插值像素置换，绑定原始父图与处理回执。补边前的32倍编辑裁片只在原始链与正式注册回执完全核对后才可继续处理，禁止3X游戏图升格。

对应独立回归为 `tests/interface_port_geometry_contract.py`，纳入软件整套资格。几何/Alpha通过仍须检查实际3X组合与高清材质；不自动批准美术或实机。

### 1.3.7：共用地面材质父图

新增 `registered-terrain-family`：真实高清二维补片、最小误差切缝、共用翻转边界及显式中心装饰保留。严格原生槽位和来源绑定，拒绝3X升格，不自动判美术或游戏通过。说明见 [TERRAIN-TEXTURE-FAMILIES.md](地图拼接与材质检测工作流.md)。

### Gemini 棋盘格底图处理（2026-10-26）

`checkerboard-alpha` 用于对 Gemini 生成图里的棋盘格底色做保守抠除，入口位于 `{H3TierExport}`。支持 PNG/JPG/JPEG；批量输入可重复传入 `--input`。输入路径、实际尺寸和 SHA 写入回执，输出写入全新目录，不覆盖原始下载图。

```powershell

```

背景判断不够明确时会标记 `REVIEW_REQUIRED`，不得把不确定颜色擦除后直接入库。检查候选时重点看细发丝/羽毛、半透明雾效、边缘晕光和主体内部空洞；棋盘格被去除不代表主体、Alpha、注册或游戏资源合同已通过。发行版操作步骤见随包的《H3TierExport-使用说明.md》。


### 1.3.11：非整数采样倍率的原图边缘去污

可对绑定真实接收原图的RGBA做有限透明边缘去污。`source.original_source_receipt`必须是`h3.art.original-received-source.v1`，并按槽位、原图路径／SHA／像素尺寸绑定。工具只在Alpha零区可达且距其有限半径内选取指定RGB颜色，使用邻近干净像素修复RGB，透明度及未选像素严格不变。该操作能处理诸如1254×1254这类不能无损写成整数原生工作倍率的模型原图；运行前不缩放或补边，输出只标记为`raw-original-resolution-candidate`，仍需检查画面质量和正式注册。


#### 1.3.12 增补：无邻色像素保持原样

透明边缘钥匙色算子把匹配像素限在同一4连通的低Alpha边带，再从真实不透明邻色向边缘传播。无法在限定半径内沿该边带取得邻色的像素不会用远处材质填补，保留原始RGBA并计入未清理残点。Alpha和选区外像素完全相同。批次仍须检查未清理残点及正常尺寸效果，不能只凭`verify`定美术通过。


1.3.13对原图无邻色的外缘色键像素不做插值猜色：只沿Alpha边缘附近的实际低Alpha像素推进，搜索距离不超过8px；不能找到真实不透明供色时，像素保持原RGBA并统计为unresolved。Alpha=1或Alpha=0透明语义不更改。


1.3.14新增`transparent-edge-low-alpha-key`模式，用于原始模型输出中已知的浅色／亮色极低Alpha外边污染。它要求精确绑定原图，且键色、Alpha上限与边缘搜索半径全部显式冻结；仅处理透明外缘连通区域中完全同色且Alpha≤上限的像素，输出Alpha0并清除隐藏RGB。边缘普通材质色及Alpha更高轮廓逐字节保留；算子不作重绘判断。最终图仍需正常尺寸复核、再注册和实际3X邻接检查。

## 画前档案与成品批量验证

> 合并来源：`ART-BATCH-QUALITY.md`。本节保留原有技术记录；历史状态以对应收据和当前软件实际行为为准。

`scale-layout` 已接入现有工具的 CLI 与任务面板。同一个 `h3.art.production-profile.v1` 档案提供开工提示词、官方槽位清单、检测依据及无损布局目标；档案绑定项目唯一美术规范的路径、版本和 SHA，不是第二份美术标准。

先用 `scale-layout quality-init` 建档，选择 `creature-actions`（生物动作）、`town-animation`（动态建筑）、`mounted-heroes`（骑乘人物）、`roads-rivers`（河流道路）或 `ground`（地面）。输入明确身份、inventory 路径/SHA、母版根和规范路径/SHA。可用 `--groups`、`--frames` 选择真实槽位子集；例如骑乘静态五朝向只选实际五组的 frame 0，不能把它说成完整动画。工具生成 production-profile.json、manifest.json 与中文 generation-brief.md。补齐参照/身体标点后用 `quality-freeze` 重新冻结；制作后或改图后也需重新冻结 SHA。

任务面板选择“人物尺度与批量质量验证 scale-layout”，载入质量 manifest，依次检查、运行、复验即可。CLI 也可 `scale-layout check|run|verify --manifest ... --manifest-sha256 ... --outdir ... --operation-id ...`。质量清单输出限新的 `build/experiments/scale-layout/<operation-id>` 或直接脚本的 batch-quality 根。结果是 JSON、引用现有原图的浅色 HTML 和画前文档，不另存图片、拼板或倍率套。检查不改原图，复验会核对当前目录、全部源 SHA 和档案。

### 已能执行的检查

- 按钉住的 inventory 逐槽核对官方路径、缺图、多图、重复文件及提供的精确别名要求；不靠文件名前缀猜范围。
- 显式子集不会把同身份未选组/帧的合法PNG误报多图；单列范围外官方帧。非槽PNG先列资料风险，原生不存在的数字组帧名才列明确名称错误；保留当前参考/来源材料，不自动删除。
- PNG 解码、单帧格式、RGBA、空图、真实 Alpha 透明。RGBA 全部 alpha=255 仍是“不存在真实透明背景”。地面模式改验应有的不透明底。
- 棋盘纹理诊断：只取真实不透明中性色角区，比较两轴交替与对角同相；支持轻微不规则棋盘。纯色、条纹和查看器在透明像素背后显示的棋盘不视为该纹理。它是风险诊断，不是抠图遮罩。
- 长直切边、碎片长宽异常、大型分离连通域、小孤岛和同动作家族色差。均记录实测与风险，不用其自动拒图/重绘，更不冒充肢体或人物数量识别。
- 身体尺度：档案提供身体折线标点、source SHA、可比姿势类、朝向目标，以及真实 native-review 注册回执后，换算为共同原生单位比较。实际采样密度来自 registered canvas，不用向上取整的 common_k 或 alpha 框。未标点的帧明确 `NOT_MEASURED`。

### 不能伪报通过的项目

普通 Alpha/连通域算法无法可靠判定多肢少肢、身份装备、动作含义或“一个完整人物”。没有部署本地语义/骨架模型时，这些项列入未测量；用户确认的坏样本标签与算法实测分开保存。人物相连、另一人物残肢、被切去头部等问题不能靠“只有一个连通域”放行。

新增真实样本：CPSYEL/0_6.png（用户确认人物不同）、CSTONE/0_6.png（明显色差）、CSTORM/1_0.png（体型偏小）。原正式版本仅对CPSYEL报色差，并未自动认出身份；CSTONE相对混合组中位色的距离21.79，低于原25的提示线，因此漏报；CSTORM在没有身体标点/注册证据时仍是未测量。样本路径/SHA、41帧对照及这些真实漏检记录于项目 `制作资料/人物生物/named-quality-defects-20261025-r02/defect-corpus.json`，不能把后续改进写成旧版已经检出。

为避免整组渐变或混合配色把中位色带偏，执行档案可填写 `color_references`：每项含 `identity/source{path,sha256}/selection_author`（assistant或user，准确记录真正选择者）。检测同时报告同组中位色和到已选参照中最近配色的Lab均色距离，沿用档案原有提示线，不为了单个样本降低阈值。可给同一身份多个已选材质参照，以容纳合理配色状态。参照SHA漂移直接阻断；输出 `REFERENCE_MATERIAL_COLOR_MISMATCH` 仍是软风险，不自动改色、拒图或冒充身份识别。画前文档也列出同一批配色参照。

五个预置模式分别执行对应算法：动态建筑锁定底座区域及循环边界、道路河流声明端口的Alpha/Lab接缝及有纹理区域的位移流向、地面指定平铺边界、生物真实DEF同偏移字节及官方序列、骑乘人物按身体路径和独立蹄底量尺度。只测了部分槽时，同时显示已测/总槽，整套不得变绿。真实原生节奏、实机状态仍另验，不把数值诊断当作语义审批。

### 窗口使用

进入“批量任务中心”，点击“画前档案 / 一键检测…”。选择类别、身份目录或某一个形态目录和明确的官方ID；例如狼人基础形态可直接选择 `CGNOLL_基础形态`，其根目录下的 `<组>_<帧>.png` 会按官方槽位检查。组/帧留空表示本身份全量，以逗号过滤子集时必须准确表达任务范围。官方inventory与唯一规范从工作区绑定预填，也可显式选择。没有现成档案时生成带待填输入说明、官方序列候选和槽位的草案；不会猜造身体目标。填写真实参考、工作画布、安全边距及本类检测参数后，选择“复用已定制作档案”，即可重新冻结当前SHA并运行同一套检测。

“冻结并一键检测”直接走原EXE的 `quality-init/quality-freeze → run`，输出当前报告和中文画前文档；检查报告保留未测量项，不会因为草案缺少身体标点就显示尺寸通过。JSON档案仍是高级参数的编辑入口，窗口尚不提供鼠标点选骨架或涂抹遮罩。

### 专属参数与证据

所有参数放入同一执行档案的 `strategies`，不是新的全局美术规范。关键字段如下：

| 参数 | 绑定与作用 |
|---|---|
| `native_defs` | `identity` 与真实DEF `source{path,sha256}`；解析偏移表，逐槽校对canvas/crop/origin，核实别名字节 |
| `static_regions` | `keys`、`reference_key`或真实reference PNG、`coordinate_space`、`region{coordinate_space,pixels,rectangles,exclude_rectangles}`；`region_role=static`锁定选区，`dynamic_allowed`锁定其余区域；`exact=true`表示精确RGBA合同 |
| `sequences` | 同组连续原生 `ordered_keys`、明确 `loop` 布尔值、共同坐标；比较相邻帧与循环闭合。禁止跳过中间帧伪称相邻帧 |
| `neighbor_edges` | `a_key/b_key`、`a_edge/b_edge`（north/south/east/west）、可选条带宽depth/端口区间a_span/b_span/reverse；接口长度不同时禁止自动拉伸；明确要求不透明的端口断开为确定错误 |
| `flow_sequences` | 连续原生顺序、相同坐标下的region、`expected_direction:[dx,dy]`、`maximum_shift_pixels`；相关匹配歧义/无纹理/区域超出有界计算预算时未测量，不声称水流方向合格 |
| `seamless_repeat` | 地面显式true时测自身东西/南北边，false时该自平铺项不适用；具体邻接仍可单独提供 |
| `animation_applicable` | 静态道路/河流显式false时不套用循环或流动检查，不能同时声明动态序列 |
| `semantic_reviews` | 路径/SHA绑定的真实 `h3.art.semantic-review.v1`；每项包含key、image_sha256、identity/character_count/anatomy/pose四项结论及实际review_author（assistant/user）。生物帧可额外填写 `background_integrity`，该项独立显示；缺少时保持 `NOT_MEASURED`。图片改变后旧判断不能复用；这不是本地模型推理 |
| `motion_reviews` | 生物动作专用的 `h3.creature.motion-review.v1`，绑定官方 inventory SHA、完整组帧顺序及每帧 SHA；逐相邻转场记录身份、解剖、装备、颜色/材质和动作逻辑结论，并明确该组是否循环。只读人工/AI语义证据；像素差异诊断不替代这项判断 |

策略坐标只接受当前源像素或现有 `native_canvas_3x`。使用后者须提供同源SHA、同inventory及真实几何的native-review报告，并核验其实际3X PNG SHA。只读检查所有正Alpha，包括alpha=1；不会擦边或降低门槛。该视图裁片检查不替代正式expand/expand-verify交付。

#### 生物动作连贯复核

用 `python -B scripts/creature_motion_review.py --manifest <冻结scale-audit-manifest.json> --operation-id <唯一ID>` 生成 SHA 绑定的逐组转场模板。模板只从官方 inventory 读取真实组帧，不猜待机、行走、攻击等组语义；每组需由审阅者选择 `loop` 或 `non_loop`，逐个查看连续转场并填写身份、解剖、装备、颜色/材质与动作逻辑状态。动作可以采用与官方不同的合理姿势，只要角色身份和变化过程自洽。将完成的模板以 `{path, sha256}` 放进 profile 的 `strategies.motion_reviews` 后重新冻结质量任务。缺模板或未测字段继续为 `NOT_MEASURED`；SHA 漂移、缺帧、跳帧或伪造循环边界会阻断复验。此项不会修改PNG，也不会按像素差阈值自动拒图。

每个身体指标都参与档案容差检查，不能只让主指标通过而忽略骑手或坐骑。动画的Alpha支持范围/质心/像素变化只是诊断，不称作骨架或身体测量。低Alpha外延和暗色半透明外延计数也只诊断，不自动去污或拒图。checkerboard 检查通过不等于背景干净；平滑光晕、软雾等仍需人工检查并绑定 `background_integrity`。

### 修复与重绘

完整高清原图可用同档案的 `h3.subject-scale-layout.manifest.v1` 进行整数裁切、透明补边与移动；全部正 Alpha 和绘画像素原样复制。缺画、结构错误、低清来源或身体目标与原生 FIT 冲突，才转单张定向重绘。正式采样与3X注册继续使用原 exporter，不放大低倍率图冒充高清母版，不擦除正 Alpha 来迎合几何。

### 手工解剖标点

画前档案对话框本身没有鼠标骨架点选。需要记录身体尺度时，可使用 `scripts/creature_landmark_annotator.py`：它载入当前冻结的 `scale-audit` manifest，按源图尺寸与 SHA 显示官方槽位，手工点选头部、躯干、全身路径和根部锚点，另需手工填写可比较姿势组与朝向。它只写新的 `h3.creature.scale-landmarks.v1` JSON，不改 PNG，也不从 alpha 框猜身体大小。完整命令、字段和限制见 `docs/creature-landmark-annotation.md`。

### 2026-10-26 新增：地图占领旗帜与战船全朝向批量质检策略 (adventure-flags / boats)

为彻底解决大地图资源中“旗帜大小不一/白化断缝”与“战船朝向体量漂移/水线错位”的长期顽疾，本地批量质检框架（`art_quality_strategies.py`、`art_batch_quality.py`、`art_production_profile.py`）新增了两类工业级数学验收策略：

#### 1. `adventure-flags`（大地图占领旗帜质检策略）

- **工作画布与实体高度统一**：所有 8 色旗帜（`0_0` ~ `0_7`）严格限定在 $900 \times 1200$ 工作画布内，实体高度统一锁定在 $1100 \pm 20$ 像素（实测 1099~1100 像素，误差 $\le 0.1\%$）。
- **旗杆立柱主轴数学对齐**：通过下立柱区间（$y \in [1050, 1150]$）的横截面质心计算立柱物理轴线，消除旗面飘动对立柱测量的干扰。全量旗杆立柱绝对统一对齐在 $X = 205.0 \pm 0.8$ 像素（容差 $\le 10$px），杜绝游戏内换色时旗杆摇晃漂移。
- **立杆连接处抗白化断缝**：在立杆与旗面接合区域严格统计非抗锯齿的白色毛刺杂像素（$\text{RGB均值} > 200$ 且 $\text{Alpha} \in (10, 240)$）。白晕像素必须 $\le 80$（实测仅 1~64 像素），彻底根除原版白色镂空断缝。
- **画布四周纯净安全留白**：顶部、左侧、右侧及底部除接地底座外的 10 像素外框纯透明无杂点（实测 0 杂点）。

#### 2. `boats`（大地图战船全朝向透视与水线质检策略）
